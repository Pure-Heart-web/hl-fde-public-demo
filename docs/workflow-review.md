## 设计与复用

原 README 要求纯合成、本地确定性规则、引用逐字检查、来源失效撤销、未测指标为 null；现有主页面与旧版85/58演示已具备相关逻辑。仓库基线没有 package.json、独立测试脚本、CI 或 AGENTS.md。新实现复用 `SemanticDemo.create/docs/usable/draft/invalidate`，不重写工程规则，不加入模型、网络、文件上传或新推理。

增加 `DemoWorkflow` 管理单次结果的证据打开和人工确认。异常卡复用三个候选的现有判断与引用：A工况缺口、B证据不足、C温度不符。7条唯一引用全部打开后，明确的处理状态、非空合成备注和勾选声明共同解锁“确认并保存”；随后才能导出 `SYNTHETIC_VERIFICATION_REPORT`。

报告保留合成来源、版本、原句行号、规则结果、未决澄清项、打开记录、当前结果的确认和审计。确认范围固定为 `LOCAL_SYNTHETIC_REVIEW_ONLY`，最终型号仍 null、客户确认 false、外部写入 0、模型指标 null。未保存草稿单独标记，不冒充已确认内容。修改复核字段会撤销确认；保存草稿不会替代人工确认。切换、重跑和失效后不能继承旧确认。失效与引用拒绝只导出 `SYNTHETIC_DIAGNOSTIC_ONLY`。

“打开”只证明本地交互发生；本页没有用户身份认证或可信审计存储，也不证明真人阅读理解、客户验收、工程合格或业务放行。

## 演示步骤

1. 打开根目录 `index.html`，进入“需求—规格对照”，选择默认 R1资料包及“不同单位 · 85000 litres/hour”。
2. 运行本地模拟。查看三条异常，核对受控换算为85 m³/h且保留32m和介质条件。
3. 点击顶部动线中的“打开一条待看证据”7次，或手动打开异常卡中的全部唯一引用。检查原文、版本、行号、引用高亮与“已打开”状态；资料卡预览不计为逐行证据查看。
4. 选择“等待客户补充资料”，填写“合成演示：当前曲线及介质条件需补充。”，勾选声明，点击确认保存。
5. 可选生成澄清模板并编辑；点击“导出核验报告 JSON”，检查报告类型、合成标记、确认范围、未决问题和null指标。
6. 修改备注，确认导出重新锁定；保存草稿不能解锁。重新确认后模拟来源失效，检查备注、草稿、候选、发现、审计和确认均撤销；只能导出诊断。
7. 切换R2，确认95要求使A变为证据不足；体验出口压力语义陷阱及错误引用拒绝。展开旧85/58演示，确认冲突与撤销仍可使用。
