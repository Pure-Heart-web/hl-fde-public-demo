# 猴来工作室 · 工业AI资料核验演示 V2

公开页面：https://pure-heart-web.github.io/hl-fde-public-demo/

面向中小型泵阀、非标设备制造及出口企业，展示报价、订单批准前的“需求—规格语义对齐与证据矩阵”。全部为人工设计的合成资料；不代表生产环境验收、选型建议或客户验证。

## 本版可以体验

- 三种预置表达：85 m³/h、85000 litres/hour、明确语境下的 pump capacity。
- 原文事实、受控换算、语义提案分开显示；点击引用可查看完整合成来源及行号。
- 三个合成型号：A仅有条件性支持，B缺Q-H工况证据，C温度硬约束不满足。
- R1→R2要求变更（85→95）；出口压力与扬程语义陷阱；注入错误quote拒绝提案。
- 模拟来源失效，撤销事实、候选、观察、发现、人工记录与草稿。
- 本页内存中的人工复核留痕、澄清模板、编辑、保存、剪贴板复制及JSON导出。
- 12项可实际运行的静态模拟器Golden检查；不输出虚构的真实模型成绩。
- 保留原85/58冲突、一致和失效基础演示，可展开体验。

## 明确区分实现与计划

**本地实际执行：** 预置资料的引用逐字比对、有限规则判定、单位算式、模板与表单、内存记录、复制、JSON下载、12项演示检查。

**人工预设：** 语义候选、来源文本、产品目录、曲线点摘录、工程规则和人工Golden预期。页面没有通用自然语言解析、PDF/Excel摄取或任意目录检索能力。

**尚未接通：** DeepSeek或其他模型API、A3可信后端、真实来源完整性/新鲜度机制、自动曲线读取、真实模型对比评测与工程师工时测量。预设引用匹配不等于A3认证。

**后续实验计划：** 60个合成质量案例（术语20、需求对照20、候选初筛20），攻击/失效另外统计；规则/字典基线、模型、模型+术语/检索/计算在同一数据版本比较，留出盲测。此数据集及对比尚未在本公开演示中实施。未测量的延迟、Token、费用、模型质量保持null。

团队软件交付基础和市场定位为团队自述；不公开客户名称、经营数据或内部审查资产，不把软件服务经验写成本项AI能力已经通过客户验收。

## 工程参考与边界

以下资料只支持一般工程概念，不支持合成型号性能，也不构成厂家或机构背书：

- [Grundfos · Pump curves](https://www.grundfos.com/au/learn/research-and-insights/pump-curves)：Q-H关系、转速及系统特性；不能将不同极值拼为保证点。
- [KSB · Head](https://www.ksb.com/en-global/centrifugal-pump-lexicon/article/head-1115612)：泵扬程、系统扬程以及不同扬程概念的区别。
- [Hydraulic Institute · Pump Curves](https://datatool.pumps.org/pump-fundamentals/pump-curves)：流量、扬程、效率、功率、NPSHR与适用条件；黏度影响不能忽略。

正式选型还需批准的性能曲线、实际介质、材料/密封适用性、功率效率、NPSH和允许运行区域，由工程师核实。PN/Class、电机功率/轴功率/水力功率、系统总量/单泵量不自动合并。本页不执行工程保证或业务放行。

## 完整操作动线（合成演示）

1. 在“需求—规格对照”选择合成询盘资料包，可选 R1、多单位表达、R2 变更或压力语义陷阱。复用预置材料；不新增文件摄取或任意文本理解。
2. 点击“运行模拟语义核验”。“发现异常”集中展示 A 的工况缺口、B 的配对点证据不足和 C 的温度硬约束，复用原有候选规则。
3. 点击异常引用或动线中的“打开一条待看证据”，随后可在原文旁连续查看“下一条异常证据”，查看来源 ID、版本、行号和完整原句。重复引用只记一次，当前预设共 7 条异常证据；打开记录仅说明交互发生，不证明理解或来源认证。
4. 选择处理状态、填写**合成**核实备注，勾选本地复核声明，点击“确认并保存本地复核记录”。待复核、空备注、缺引用或未勾选均不能确认。人工确认只保存处理记录，不消除异常，不批准选型或报价。
5. 在复核区点击“导出核验报告 JSON”。报告包含异常、原文证据、打开记录、本地确认、未决澄清项和明确的合成边界；未保存草稿另列 `current_local_edits`，未测模型指标保持 `null`。

修改复核备注、状态或声明会撤销当前确认，须再次点击确认。更换资料、表达、错误引用条件、重新运行、重置及模拟来源失效均不继承旧确认。来源失效／引用拒绝只能下载 `SYNTHETIC_DIAGNOSTIC_ONLY` 诊断记录，不会伪装成已复核报告。原85/58基础体验仍为独立演示，其原始记录下载不属于这条新报告动线。

## 自动检查与体验验收

运行时仍只需本地 HTML/CSS/JavaScript，新增 `workflow.js` 仅管理演示交互门禁。Playwright 只用于开发检查，不会加载到公开页面。

```sh
npm ci --ignore-scripts
npm run check
npx playwright install chromium
npm run test:browser
```

`npm run check` 包含原 12 项 Golden 和新增的门禁、撤销、报告及静态隔离检查。浏览器检查覆盖桌面、390px / 320px 布局、完整报告下载、失效诊断、切换竞态、旧版体验、键盘定位和 HTTP 下 CSP；截图输出到 `test-results/`。可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已有 Chromium。检查结果只针对静态合成模拟器，不是模型质量、客户验收或实际性能测量。

GitHub Actions 对 PR 和 main 执行检查并保存截图工件，权限只读；没有增加自动部署或合并步骤。Pages 仍从 main 根目录发布，合并本 PR 会按既有 Pages 配置更新公开页面。回滚应恢复本变更之前的文件内容生成新提交，不强推历史。

演示路线、实际测试证据及仍需人工体验的清单见 [核验动线验收记录](docs/workflow-review.md)。
